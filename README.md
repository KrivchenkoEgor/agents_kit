# Агент данных розничного магазина

Проект родился на практике: категорийные менеджеры торговой сети
постоянно нуждаются в новых срезах продаж, а каждый запрос к
разработчикам — это дни ожидания. Этот репозиторий — рабочая
«лаборатория», в которой менеджеры на живых данных розничных продаж
учатся самостоятельно, быстро и без привлечения разработчиков
прототипировать управленческие отчёты: от простой выгрузки до
многостраничного дашборда.

## Что это даёт

- **Самостоятельность.** Любой сотрудник, владеющий Excel на базовом
  уровне, за один сеанс с ИИ-ассистентом получает готовый отчёт:
  формулирует задачу словами — ассистент пишет код, объясняет его и
  показывает результат.
- **Скорость.** Прототип отчёта — от задания до файла — занимает
  минуты, а не дни: не нужен бэклог разработчиков, согласование
  формата и релизные циклы.
- **Прозрачность.** Каждый скрипт — это нумерованный, прокомментированный
  шаг: загрузка, очистка, анализ, визуализация. Понятно, как получена
  каждая цифра, и любой отчёт можно пересчитать самому.
- **Обучающий эффект.** Ассистент не молча выполняет задачу, а
  объясняет логику простыми словами с жизненными аналогиями — так
  менеджеры постепенно осваивают анализ данных и перестают зависеть
  от «посвящённых».

## Самообучающийся ИИ-агент

В основе проекта — ИИ-ассистент, который учится на собственном опыте
прямо внутри репозитория. Его правила, накопленные приёмы и состояние
живут в md-файлах:

| Файл | Роль |
|---|---|
| `AGENTS.md` | «Конституция» ассистента: личность, правила работы с данными, стиль общения |
| `LESSONS.md` | Журнал уроков: каждая решённая задача оставляет в нём приём или грабли — в следующий раз ассистент уже знает, как не наступить |
| `progress.md` | Дневник проекта: что сделано и в каком порядке |
| `checkpoint.md` | «GPS» состояния: что делается сейчас и какой шаг следующий |

Так агент помнит проект между сессиями и с каждой задачей становится
точнее — без внешних сервисов и дообучения моделей: обучение идёт
через собственный журнал уроков и конституцию проекта.

Навигацию по кодовой базе ускоряет **MCP-сервер codegraph** — граф
символов и связей между скриптами: вместо многошагового поиска по
файлам ассистент мгновенно получает нужные фрагменты кода и понимает,
какие части проекта затронет изменение.

## Что умеет проект

**Анализ продаж**

- **Разведка данных** — чтение файла целиком, базовые статистики, пропуски, дубликаты.
- **Аудит ассортимента** — кто менялся: коды с несколькими названиями, ушедшие
  и пришедшие товары, разбор фасовок из названий.
- **Декомпозиция падения продаж** — почему упали продажи (по периодам,
  группам товаров, штукам/объёму/выручке).
- **Помесячная аналитика** — таблицы «год × месяц», товары помесячно
  и по годам, готовые к срезу в Excel.

**Шринкфляция и истории товаров**

- **Поиск шринкфляции** — пары «ушёл → пришёл» одной марки с меньшей
  фасовкой; цены до/после смены и подорожание относительно фона магазина.
- **Истории товаров** — склейка смен фасовок в непрерывные «истории»
  по правилу пользователя, чтобы считать динамику честно.

**Классические управленческие отчёты**

- **ABC-анализ** — кто приносит деньги: пулы A/B/C по выручке, объёму
  и наценке, звёзды и аутсайдеры (молоко и колбаса по группам).
- **XYZ-анализ** — насколько спрос предсказуем: стабильные, колеблющиеся
  и непредсказуемые товары (классические и розничные границы).
- **Матрица ABC × XYZ** — 9 категорий с практическими рекомендациями
  по закупкам: от «планируй точно» до «кандидаты на снятие».
- **Хвост ассортимента (группа C)** — кто сидит в последних 5% выручки
  и что с ними делать.
- **Судьба новинок** — кто пришёл в ассортимент и что из них вышло.
- **Топ-5 по группам** — самые продаваемые позиции каждой категории.
- **Топ по валовой прибыли** — кто зарабатывает магазину больше всего
  (выручка и наценка по периодам и группам).
- **Потерянные топ-товары** — лидеры прошлых лет, которых нет в продажах
  сейчас: сколько выручки потеряно и почему.

**Прогнозирование**

- **Прогноз на остаток года** — модель «тренд × сезонность».
- **Подневный прогноз** — на каждый день месяца по каждому товару.
- **Сверка прогноза с фактом** — честный отчёт о точности прогноза
  по товарам и периодам.

**Дашборд**

- **HTML-дашборд** — офлайн-витрина показателей для руководителя:
  финансы, натуральные продажи, ассортимент, прогноз; переключатели
  категорий, выбор года, сортировка — всё пересчитывается на лету.

**Контроль качества**

- **Контрольные сверки** — после каждого расчёта суммы сверяются с
  эталонами, чтобы цифры в отчётах были честными; сверка версий
  отчётов между собой.

## Технологии

Python 3.8, pandas, openpyxl, matplotlib; дашборд — чистый HTML/JS
с Chart.js (локально, работает без интернета); навигация по коду —
MCP codegraph. Без фреймворков и без облачных сервисов.

## Структура репозитория

| Каталог | Назначение |
|---|---|
| `scripts/` | Нумерованные шаги: загрузка → очистка → анализ → отчёты → дашборд |
| `output/` | Результаты: Excel-отчёты и HTML-дашборд |
| `plots/` | Графики для быстрого визуального контроля |
| `data/` | Исходные данные магазина (реальные продажи, в репозитории) |
| `AGENTS.md`, `LESSONS.md`, `progress.md`, `checkpoint.md` | Память самообучающегося ассистента |

## Карта скриптов

Каждый скрипт — нумерованный шаг с русскими комментариями: запускается
командой `python3 scripts/<имя>.py` из корня репозитория.

| Скрипт | Что делает |
|---|---|
| `01_explore.py` | Разведка данных: чтение файла целиком, базовая статистика, пропуски, дубликаты |
| `02_assortment_audit.py` | Аудит ассортимента: коды с несколькими названиями, ушедшие и пришедшие товары, фасовки в названиях |
| `03_decompose_decline.py` | Разложение падения продаж на факторы (по периодам, группам, штукам/объёму/выручке) |
| `04_shrinkflation_pairs.py` | Поиск пар «шринкфляции»: та же марка, меньшая фасовка (ушёл → пришёл) |
| `05_monthly_by_year.py` | Помесячный анализ: «год × месяц», товары помесячно и по годам → Excel |
| `06_build_chains.py` | Построение «историй товаров» с учётом шринкфляции (правило пользователя) |
| `07_decompose_chains.py` | Декомпозиция падения продаж с учётом склеенных «историй» |
| `08_shrinkflation_prices.py` | Цены до/после смены фасовки: что стало с ценой за кг |
| `09_background_prices.py` | Подорожание при шринкфляции относительно фона всего магазина |
| `10_abc_analysis.py` | ABC-анализ (20/80): пулы A/B/C по выручке и по штукам |
| `11_group_c.py` | «Хвост» ассортимента: кто в группе C и что с ними делать |
| `12_newcomers.py` | Судьба новинок: кто пришёл в ассортимент и что из них вышло |
| `13_forecast_2026.py` | Прогноз на остаток года: модель «тренд × сезонность» |
| `14_forecast_august_daily.py` | Подневный прогноз месяца по каждому товару |
| `15_compare_august_forecast_fact.py` | Сверка прогноза с фактом: честный отчёт о точности |
| `16_lost_top_products.py` | Потерянные топ-товары 2023 (нет в продажах 2026) |
| `17_lost_top_products_2024.py` | Потерянные топ-товары 2024 (нет в продажах 2026) |
| `18_abc_sausage.py` | ABC-анализ колбасы по группам: выручка, объём, наценка |
| `19_top5_sausage.py` | Топ-5 самых продаваемых позиций в каждой группе |
| `21_lost_top_products_v2.py` | Потерянные топы 2023 и 2024, версия 2 (пересчёт по общему правилу) |
| `22_top_profit_sausage.py` | Топ по валовой прибыли (наценке) за всё время, по группам |
| `24_compare_lost_top_files.py` | Сверка версий отчётов о потерях между собой |
| `25_inspect_output.py` | Обзор структуры всех книг в `output/` |
| `26_build_dashboard_data.py` | Сбор данных дашборда в единый JSON с контрольными сверками |
| `27_generate_dashboard.py` | Генератор интерактивного HTML-дашборда |
| `28_xyz_analysis.py` | XYZ-анализ: предсказуемость спроса (классические и розничные границы) |
| `29_abc_xyz_matrix.py` | Матрица ABC × XYZ: 9 категорий с рекомендациями по закупкам |

## Как запустить

Установка зависимостей:

```bash
pip install -r requirements.txt   # pandas, openpyxl, matplotlib
```

Пример пайплайна «колбаса целиком» — от анализа до карты решений:

```bash
python3 scripts/18_abc_sausage.py        # ABC по группам → output/Отчет_ABC_колбаса_группы.xlsx
python3 scripts/19_top5_sausage.py       # топ-5 позиций каждой группы
python3 scripts/22_top_profit_sausage.py # топ по валовой прибыли
python3 scripts/28_xyz_analysis.py       # XYZ: предсказуемость спроса → Отчет_XYZ_колбаса.xlsx
python3 scripts/29_abc_xyz_matrix.py     # матрица ABC × XYZ → Отчет_ABC_XYZ_колбаса.xlsx
```

Сборка дашборда руководителя:

```bash
python3 scripts/26_build_dashboard_data.py          # данные → dashboard_data.json
python3 scripts/27_generate_dashboard.py            # → output/dashboard/Дашборд_магазина.html
```

Каждый скрипт печатает контрольные сверки («КОНТРОЛЬ … OK») — если цифры
разошлись с эталоном, он честно об этом сообщает. Результаты открываются
из `output/` двойным кликом; графики — в `plots/`.

## Примечания

- Это учебно-рабочий проект: цифры основаны на реальных продажах
  магазина и пригодны для управленческих решений, но методика
  намеренно простая — её может повторить любой менеджер.
